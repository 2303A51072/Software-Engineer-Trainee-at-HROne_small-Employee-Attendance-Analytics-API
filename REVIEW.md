# REVIEW.md

I found these defects in the starter `app/main.py`:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | It relies on a naive datetime and treats it as if its wall clock were the shift's IST time. Its `> 10` check also loses the strict 10-minute-plus-one-second boundary after integer conversion. | For a 09:30 IST shift, 09:40:01 must produce 10 late minutes; run the same request on a host with a non-IST timezone. | Convert the UTC instant to IST, compare it with the shift start, and apply the strict 600-second threshold before flooring minutes. |
| 2 | `compute_late_minutes` / punch-in | It does not anchor a morning punch for an overnight shift to the preceding shift-start date. | Punch in at 05:00 for a 22:00-06:00 shift and inspect its date and late minutes. | Derive the record's shift date using the overnight rule and calculate lateness from that shift's start. |
| 3 | `compute_work_hours` | Python's built-in `round` uses ties-to-even rather than the required decimal half-up rounding. | Use a duration whose hours round exactly at a half-cent boundary. | Calculate from whole seconds with `Decimal` and `ROUND_HALF_UP`. |
| 4 | `compute_overtime` | It combines a UTC/naive punch-out with an IST shift-end, and always puts shift end on the record date. | Test a UTC instant, an overnight shift, and a punch-out 29 minutes versus 30 minutes after shift end. | Build the shift-end instant in IST on the correct date and count only whole minutes when overtime reaches 30 minutes. |
| 5 | `create_employee` | Checking for a duplicate before inserting is a race and there is no unique database guarantee. `created_at` is also a naive datetime. | Send two simultaneous requests for one `emp_code`; compare the stored and returned creation instant. | Enforce uniqueness with a MongoDB index, map duplicate-key errors to 409, and store a UTC-aware timestamp. |
| 6 | `list_employees` | The offset skips the first page, `total` ignores the department filter, results are not sorted, and invalid page values are accepted. | Request page 1 with a non-empty collection and then filter to a department. | Use `(page - 1) * page_size`, count the filtered query, sort by `emp_code`, and validate pagination. |
| 7 | `health` | It reports success without checking MongoDB, so an unavailable database looks ready. | Stop MongoDB and call `/health`. | Ping MongoDB and return 503 when the ping fails. |
| 8 | `punch_in` | A missing employee causes a `TypeError`/500; status is unrestricted; timestamps use the host timezone and a truthiness check; seconds, floats, strings, and out-of-range values are not rejected. | Try an unknown code, an invalid status, `punched_at: 0`, seconds, a float, and a request on a non-IST host. | Validate request models and timestamp bounds, convert epoch milliseconds in UTC, and return 404 for an unknown employee. |
| 9 | `punch_in` | The duplicate pre-check cannot prevent concurrent duplicate attendance documents, and the response exposes an internal Mongo id as `id`. | Send parallel punches for one employee/date and inspect the response shape. | Enforce a unique `(emp_code, date)` index, handle duplicate-key errors as 409, and omit internal ids. |
| 10 | `punch_in` / `attendance_date` | The starter uses the machine's local date rather than the IST attendance date and does not apply the overnight-shift date rule. | Use an epoch instant near IST midnight or an overnight punch before shift end. | Derive the attendance date in IST and anchor early overnight punches to the shift's starting date. |
| 11 | `list_attendance` | It loads every matching record into application memory, does not validate pagination or date order, and does not apply the required secondary sort by employee code. | Exercise it on a large dataset, request page 1, or pass `date_from > date_to`. | Count with the filtered query, sort/page in MongoDB, validate inputs, and add query-supporting indexes. |
| 12 | Missing endpoints | Punch-out, regularization/audit history, all four analytics operations, and explain were not implemented. | Call each contracted route. | Implement the routes, business rules, database aggregations, and explain operations. |

**Checked and kept:** the starter's default punch-in status is `PRESENT`, matching the contract. Keeping `date` and `joined_on` as `YYYY-MM-DD` strings is also correct; they are calendar values, not instants.
